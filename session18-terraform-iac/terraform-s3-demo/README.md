| File | Purpose |

A local `terraform.tfvars` can override the defaults. It is ignored by Git; the current project also works with the defaults defined in `variables.tf`.

## Resource Configuration

| Setting | Value |
|---|---|
| Terraform resource address | `aws_s3_bucket.devops553` |
| Bucket name | `yatri1107` |
| Region | `ap-south-1` |
| Provider selected by the lock file | `hashicorp/aws` 6.66.0 |
| Tags | `Name=yatri1107`, `Environment=dev`, `ManagedBy=Terraform`, `Project=Session18` |
| `force_destroy` | `true` |

The resource label `devops553` is Terraform's local identifier; `yatri1107` is the AWS bucket name. General purpose bucket names in the shared namespace must be unique within an AWS partition. A repeat run may require a different bucket name. [AWS bucket naming rules](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucketnamingrules.html)

## Terraform Workflow

### 1. Configure AWS Access

From the repository root:

```bash
aws configure
aws sts get-caller-identity
cd session18-terraform-iac/terraform-s3-demo
```

The CLI configuration uses an access key ID, its secret key, `ap-south-1` as the region, and `json` as the output format. Credentials remain outside the project. [AWS CLI configuration](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)

### 2. Initialize, Format, and Validate

```bash
terraform init
terraform fmt
terraform validate
```

Initialization selected AWS provider **6.66.0** from the lock file. The terminal reported:

```text
Terraform has been successfully initialized!
Success! The configuration is valid.
```

### 3. Preview and Apply

```bash
terraform plan
terraform apply
```

Review the plan and enter `yes` when Terraform requests approval. The screenshot captures `terraform apply` displaying a plan to create `aws_s3_bucket.devops553`, with the bucket name, region, tags, and `force_destroy` setting.

![Initialization, validation, and the S3 creation plan](../../.screenshots/session18_1.png)

A separate `terraform plan` invocation is not visible in this capture; the preview shown is the plan generated by `terraform apply`.

### 4. Inspect State and Outputs

```bash
terraform show
terraform output
```

The captured output is:

```text
bucket_name = "yatri1107"
bucket_region = "ap-south-1"
```

![Terraform show and output displaying the saved values](../../.screenshots/session18_2.png)

The configuration also declares `bucket_arn`, but that output is not present in this screenshot. Terraform outputs expose selected values stored in state; reading them alone does not verify the current existence of a bucket in AWS. [Terraform outputs](https://developer.hashicorp.com/terraform/language/block/output)

### 5. Destroy the Demo Resource

```bash
terraform destroy
```

Review the deletion plan and enter `yes` to confirm. The resource uses `force_destroy = true`, which permits Terraform to delete bucket contents as part of bucket removal. [AWS provider S3 resource](https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/s3_bucket)

A successful removal should be recorded from the terminal's destruction summary. Neither supplied screenshot contains that summary.
